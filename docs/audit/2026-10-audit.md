# Love Islander — Technical Audit (October 2026)

Scope: the whole repository at commit `2c9670c` (frontend, Supabase edge functions, SQL migrations, storage, configuration, tooling, tests, docs). Mapped with CodeGraph and verified by reading the cited code. Paths are relative to the repository root.

> **Security disclosure note.** This repository is public. Security findings are listed by category only. A detailed appendix (affected code, reproduction, impact) will be added once the Phase 2 fixes (#4–#7) are merged and deployed to the live Supabase project.

## 1. Current architecture

```
Browser (Vite + React 18 + TS, shadcn/ui, react-query)
  │  supabase-js with the publishable key, session in localStorage
  ├──▶ Supabase Postgres (PostgREST)   ← ~170 direct call sites, RLS is the only server-side guard
  ├──▶ Supabase Storage                ← bucket `profile-images` (public)
  ├──▶ Supabase Realtime               ← `messages` inserts
  └──▶ 11 Deno edge functions          ← AI, email, Google Calendar, location, profile bootstrap
Capacitor shell (android/ios not yet generated)
```

- There is no application backend. Business rules live in React hooks/services (`src/services/**`, `src/hooks/**`) and in RLS policies.
- The single Supabase client is `src/integrations/supabase/client.ts:11` (Lovable-generated header).
- An unused axios client targets a hardcoded ngrok URL (`src/services/api/client.ts:4`), a leftover from an earlier backend.

### Routes (`src/App.tsx`)
Public: `/login`, `/signup`, `/verify`, `/terms`, `/privacy`. Private: `/onboarding`, `/profile`, `/discover`, `/matches`, `/ai-companion`, `/streaks`, `/settings`, `/feedback`, `/safety`, `/support`; `/` → `/discover`.
- Missing: `/auth/callback` (used by Google sign-in, `src/context/auth.tsx:206`), `/reset-password` (`src/context/auth.tsx:218`), catch-all 404.
- Unrouted pages: `Messages.tsx`, `UserProfile.tsx`, `Index.tsx`, `AICompanionChat.tsx`, `NotFound.tsx`.

## 3. Database

Tables (all `public`, uuid PKs): `profiles`, `profile_onboarding`, `profile_images`, `ai_chat_history`, `user_feedback`, `blocked_users`, `date_plans`, `safety_contacts`, `matches`, `messages`, `swipes`, `user_settings`, `streaks`, `streak_likes`. No enums, views, or RPCs. One trigger function `handle_mutual_swipe` (SECURITY DEFINER) and `update_updated_at_column`.

### Schema drift
Code references objects that no migration or generated type defines:
- `likes` (`db_migration.sql`, `rls_permissions.sql` — both stale; the latter references non-existent `matches.user1_id`)
- `user_memory`, `notifications`, `profile_interests`, `interests`, `user_settings.ai_companion_settings` (`supabase/functions/ai-companion-proactive/index.ts`)
- `ai_conversation_memories` with an embedding column (pgvector) — dead code in `supabase/functions/ai-companion/utils/userContext.ts`
- `profiles.latitude/longitude/location_updated_at` (`location-services`)
- Storage bucket `media`; `supabase/migration.sql` creates `profile_images` with invalid policy SQL

Whether these exist in the live project must be confirmed with a schema dump (#8).

### Indexes and triggers
- Missing: `messages(match_id, created_at)`, `messages(sender_id)`, `ai_chat_history(user_id)`, `streaks(user_id)`, `matches(matched_user_id)`, `blocked_users(blocked_user_id)`, `streak_likes(streak_id)`, `date_plans(user_id)`, `safety_contacts(user_id)`.
- Redundant: `matches_user_idx`, `swipes_user_idx` duplicate unique indexes.
- `updated_at` trigger missing on `date_plans`, `user_settings`; registered twice on `profiles`.
- Mutual-swipe trigger can create both (A,B) and (B,A) under concurrency.

### Portability blockers (Supabase-specific)
`auth.users` FK, `auth.uid()` in every policy, `anon`/`authenticated` roles, `storage.*` schema and `storage.foldername()`, `supabase_realtime` publication, `auth.admin.*` and `user_metadata` in edge functions.

## 5. Scalability
No pagination anywhere: discover (50 then client filter), matches, messages, AI history (oldest 50), streaks (20), blocked list (N+1). Per-card image re-fetch in `src/components/discover/ProfileDisplay.tsx:38`. Realtime subscription leak in chat.

## 7. What is required for production
Tracked as issues #2–#28 (see `docs/STATUS.md`):
1. Green tooling baseline without Lovable; CI.
2. Immediate security fixes on the current Supabase stack.
3. Reconciled schema → FastAPI backend with SQLAlchemy + Alembic on portable Postgres; data migration and backup runbooks.
4. Each feature moved behind the API with server-side validation, pagination, and no simulated success.
5. Rate limiting, observability, dependency/secret scanning.
6. Unit, integration, migration, API and E2E tests in CI.
7. Documentation and a verified clean-clone setup.

### External dependencies (cannot be completed from the repository alone)
Supabase project access (schema dump, JWT verification key, function deployment), OpenAI API key, Resend key and verified sender domain, Google OAuth client, production hosting target, Android signing keystore.
